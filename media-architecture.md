# StellaNova media architecture decision

## Recommendation

Do **not** add Cloudinary and Cloudflare as overlapping media systems. Use one canonical storage path and, if needed, one delivery/optimization layer.

For StellaNova, the recommended production shape is:

1. The NFT’s canonical metadata and original media live in immutable object storage or a content-addressed store. The token URI must remain stable and must not depend on a mutable thumbnail transformation.
2. Cloudflare R2 is the better default for originals and JSON metadata when StellaNova needs S3-compatible storage, a custom media domain and low-egress delivery. Attach a production custom domain rather than relying on the `r2.dev` development URL.
3. Cloudflare Images or a small image-processing worker can provide responsive thumbnails and WebP/AVIF derivatives. Do not rewrite the canonical token URI to a derivative URL.
4. Add Cloudinary only if the product needs its richer media workflow: signed uploads, automatic image analysis, advanced transformations, video processing or a non-engineering media library.

## Why not Cloudinary by default

Cloudinary is strong at upload workflows, transformations and delivery URLs. Its Upload API supports authenticated uploads, signed upload parameters, tags, metadata, incoming transformations and analysis data. Its API secret must stay server-side; even unsigned upload presets should be treated as sensitive because anyone who knows the preset can upload through it. [1]

That makes Cloudinary useful for creator uploads and editorial media, but it is not a substitute for an NFT’s canonical, durable metadata layer. A Cloudinary transformation URL should be stored as a display derivative, not as the only token URI.

## Why Cloudflare is the better first addition

R2 buckets are private by default. Production access can be exposed through a custom domain, which enables Cloudflare caching, WAF rules and access controls. Cloudflare explicitly describes the `r2.dev` URL as intended for non-production traffic. [2]

Cloudflare Images can also store, optimize and deliver images through a managed API, and Cloudflare documents remote-image transformations when originals remain outside Images. [3]

## StellaNova implementation boundary

The current Testnet contract uses a base metadata URI and the app has public contract IDs. The next production media step should add:

- immutable metadata JSON for each minted token;
- an original-media object key and content hash;
- a thumbnail URL generated by the media delivery layer;
- server-side upload authorization and MIME/size validation;
- moderation and malware checks before minting;
- an indexer/read model that records the metadata URI, media hash, owner, listing and marketplace events.

No Cloudinary or Cloudflare credentials belong in the browser bundle. If Cloudflare is selected, configure R2/Images through server-side secrets and expose only public delivery URLs to the app.
